# 沉淀一下

个人离线游戏封禁管理 Android App，开发基线版本 **0.1.2**。无需登录或 Root，Android 8.0 及以上。

## 已实现

- 账号 → 游戏 → 大区 → 角色 → 多次封禁记录，支持新增、编辑、删除。
- QQ / 微信登录类型，自定义账号标识、显示名称、游戏和大区、角色 ID 与昵称。
- 封禁时长支持天、小时、分钟组合，或选择预计解封时间，双向计算；永久封禁独立设置。
- 封禁原因、备注、截图附件；每条最多 20 张图片，单张上限 32 MB。
- 总览卡片、文本搜索、游戏与状态筛选、三种排序；当前档案与全部历史切换。
- 按角色最新封禁统计封禁中、今日预计解封、永久封禁数量。
- 预计解封、提前 24 小时、两者都提醒及不提醒；默认规则可设置。
- 点击系统通知进入封禁详情；确认实际解封会取消该次后续提醒。
- 完整 ZIP 备份，支持合并、替换、重复检查、附件恢复和恢复前校验。
- 黑金渐变卡片、细边框纹理、简短淡入过渡，四个底部导航。
- HTTPS 内置浏览器、图片选择预览入口，明确提示识别功能待完善。

## 状态与统计规则

1. 角色“当前封禁”取开始时间最新的一条；同一开始时间按添加时间、ID 排序。新增历史不会被误当成当前记录。
2. 有手动解封确认则为“已确认解封”；否则永久记录为“永久封禁”。
3. 普通记录预计解封时间大于当前时间为“封禁中”，否则为“已到预计解封时间”。到期不会自动确认实际解封。
4. “即将到期”为未来 24 小时内预计解封。今日按设备当前时区的自然日统计，已确认解封和永久记录不计入今日预计解封。
5. 总览默认只显示每个角色当前记录，开启历史开关可查全部；统计始终只计算角色当前记录。
6. 系统提醒仅为角色当前记录安排，避免历史封禁继续触发；提前一天指到期前 24 小时，当天在预计解封时刻触发。使用允许省电模式下投递的非精确闹钟，系统可能延迟通知。
7. 数据时间保存为时间戳，按设备时区显示。提醒在重启、应用更新、时间或时区变化后重新安排。系统强行停止应用后需重新打开。

## 备份语义

- ZIP 包包含版本化 `manifest.json` 及 `attachments/`，清单含全部账号、游戏、大区、角色、封禁、附件索引和设置。
- 合并优先保留本地；账号按类型和标识、游戏按名称、大区按游戏和名称、角色按账号和大区与角色 ID 匹配。
- 封禁按角色、起止时间、永久标记、原因和备注检查重复。重复记录保留本地确认状态与提醒规则。相同附件 ID 不重复导入。
- 替换保留备份中的稳定 ID 与设置；先校验版本、字段、关联和所有附件，再通过数据库事务整体替换。失败保留原始数据库与附件。
- 禁止路径穿越和未知 ZIP 条目；清单上限 8 MB，解压后总量上限 256 MB。导出也校验同一上限，避免生成无法恢复的超限包。
- 未加密，备份由使用者自行保管。源码不包含用户真实账号和截图。

## 构建

这是 Java 17 原生工程，无第三方运行依赖。可在 Android Studio 中打开并使用标准 Gradle 构建：

```powershell
.\gradlew.bat :app:assembleDebug
```

若 Gradle 依赖不可用或后台进程受限，可直接用已安装的 JDK 与 Android SDK 离线构建：

```powershell
.\scripts\build.ps1 -SdkRoot C:\Users\1657322\AppData\Local\Android\Sdk
```

需要 Android SDK Platform 36 和 Build Tools 36.0.0。输出 `dist/chendian-0.1.2.apk`，脚本完成 DEX 编译、对齐与 APK v2/v3 签名校验。手动构建的调试签名保存在 `build/manual/debug.keystore`，应保留它以便之后覆盖安装；Android Studio 默认签名与之不同。

本次产物是可安装的调试版，不是正式发行签名版。

## 验证

```powershell
.\scripts\test.ps1
python scripts\test_schema.py
.\scripts\build-tests.ps1
adb install -r dist/chendian-0.1.2.apk
adb install -r dist/chendian-tests.apk
adb shell am instrument -w cn.chendian.app.test/cn.chendian.app.AppTests
```

本机已通过 14 项时间与状态断言、12 项真实 SQLite 架构与事务断言，以及主 APK 和设备测试 APK 编译。集成测试使用独立测试数据库与临时附件目录，覆盖备份替换、重复合并、附件字节完整性、损坏备份拒绝与事务回滚。

当前环境 ADB 无法启动，因此**设备集成测试未运行，界面与通知投递尚待手机验收**。建议按下列流程验收：

1. 添加两个账号、同一游戏下两个大区与多个角色，确认角色 ID 的唯一范围。
2. 同一角色添加历史记录和当前记录，核对总览统计及历史开关。
3. 用分钟级封禁核对到期状态、系统通知、通知跳转、手动确认与撤销。
4. 添加截图后导出备份，先重复合并，再添加临时数据并替换恢复，核对附件和设置。
5. 重启手机后核对提醒，分别验证通知允许和拒绝场景。

## 主要代码

- `Store.java`：SQLite 关系模型与查询。
- `BanTime.java`：时间、状态、倒计时规则。
- `MainActivity.java`：四个主页面及录入、历史、详情流程。
- `GoldCard.java`：金属纹理渐变卡片。
- `Reminders.java`、`ReminderReceiver.java`、`BootReceiver.java`：提醒调度、通知和系统事件恢复。
- `Backup.java`：版本化备份、合并与替换。
- `BrowserActivity.java`：内置页面浏览和待完善导入提示。
